# Source Strategy

Prefer sources in this order when applicable:

1. Live runtime behavior and direct measurements.
2. User-provided primary artifacts.
3. Purpose-built authenticated connectors or APIs.
4. Official product, standards, vendor, or repository documentation.
5. Original research, filings, datasets, or maintained source code.
6. High-quality secondary analysis.

Use recency only where the claim is time-sensitive. For disagreements, compare scope,
date, definitions, methodology, and directness rather than counting sources. Cite the
source that supports each material externally verifiable claim.
